# Nibble — Snapdragon NPU Validation & Deployment Checklist

This document defines the **13-Point Engineering Checklist** required to validate, benchmark, and deploy AI models on genuine **Qualcomm Snapdragon X Elite / X Plus Copilot+ PCs** (such as the HP OmniBook X / HP EliteBook Ultra).

---

## Hardware & Architecture Prerequisites

| Parameter | Development Machine (Current) | Target Deployment Machine |
| :--- | :--- | :--- |
| **Architecture** | `AMD64 / x86_64` | `ARM64` |
| **Processor** | AMD Ryzen 5 8540U | Qualcomm Snapdragon X Elite / X Plus |
| **NPU** | *Not detected (AMD Host)* | **Qualcomm Hexagon NPU (45 TOPS)** |
| **Execution Provider** | `CPUExecutionProvider` | `QNNExecutionProvider` |
| **OS** | Windows 11 x64 | Windows 11 ARM64 (24H2+) |

---

## 13-Point Engineering Checklist

### 1. Host Architecture & Platform Verification
* Run genuine hardware detection:
  ```powershell
  python -m nibble hardware
  ```
* Verify that `CPU Architecture` reports `ARM64` and `Snapdragon Native: True`.
* Ensure the target OEM is recognized (e.g. `HP OmniBook X`).

### 2. Qualcomm Hexagon NPU Device Driver Verification
* Open Windows Device Manager (`devmgmt.msc`).
* Expand **Neural Processors** and confirm:
  * `Snapdragon(R) X Elite - Hexagon(TM) NPU` (or X Plus equivalent) is present and functioning with code 0 (no driver yellow-bang).
* Verify driver date and version matches Qualcomm NPU package release.

### 3. Qualcomm Neural Processing SDK (QNN) Installation
* Download and extract Qualcomm Neural Processing SDK (v2.24+ recommended for Snapdragon X series).
* Set system environment variables:
  ```powershell
  $env:QNN_SDK_ROOT = "C:\Qualcomm\QNN_SDK"
  $env:PATH = "$env:QNN_SDK_ROOT\lib\arm64-windows;$env:PATH"
  ```
* Test CLI utilities:
  ```powershell
  qnn-net-run --version
  ```

### 4. ONNX Runtime QNN Execution Provider Installation
* Install ONNX Runtime with native QNN EP support for Windows ARM64:
  ```powershell
  python -m pip install onnxruntime-qnn
  ```
* Verify provider availability:
  ```powershell
  python -m nibble providers
  ```
* Confirm that `QNNExecutionProvider` transitions from `UNAVAILABLE` to `AVAILABLE`.

### 5. Model Ingestion & Static Compatibility Audit
* Inspect the target ONNX model using Nibble's static analysis:
  ```powershell
  python -m nibble analyze models/target_model.onnx
  ```
* Review operator coverage score (aim for $\ge 95\%$ compute coverage on Hexagon HTP).
* Check for unsupported control flow operations (`Loop`, `If`, `NonZero`) that force CPU fallbacks.

### 6. Target Precision & Quantization
* The Hexagon Tensor Processor (HTP) operates at maximum throughput with **INT8 (weights + activations)** or **FP16**.
* Generate optimized INT8/FP16 models:
  ```powershell
  python -m nibble optimize models/target_model.onnx --target npu --precision INT8
  ```
* Ensure pre-processing data transforms and scale factors are embedded or calibrated.

### 7. Graph Partitioning Verification
* Review the graph partitioning plan generated by `nibble.partitioner`:
  * Subgraphs mapped to `QNNExecutionProvider` (NPU).
  * Subgraphs falling back to `CPUExecutionProvider`.
* Confirm that tensor transfer overhead between NPU and CPU boundaries is minimized.

### 8. Hexagon Tensor Processor (HTP) Context Binary Cache Generation
* In production, compiling the ONNX model to HTP microcode on first run causes high cold-start latency.
* Generate a pre-compiled QNN context binary cache (`.bin`):
  * Pass session options:
    ```python
    session_options.add_session_config_entry("session.qnn.htp_performance_mode", "burst")
    session_options.add_session_config_entry("session.qnn.context_cache_enable", "1")
    session_options.add_session_config_entry("session.qnn.context_cache_path", "models/target_model_cache.bin")
    ```

### 9. Cold-Start vs Warm-Start Benchmark Validation
* Measure cold-start initialization latency (model load + provider graph compilation).
* Measure warm-start inference latency across 100 measured iterations:
  ```powershell
  python -m nibble benchmark models/target_model_opt.onnx --backend "Snapdragon NPU" --warmup 10 --runs 100
  ```
* Confirm that warm-up runs are completely excluded from measured percentile metrics.

### 10. Mathematically Consistent Latency & Throughput Reporting
* Execute side-by-side verification:
  ```powershell
  python -m nibble compare models/target_model.onnx models/target_model_opt.onnx --backend "Snapdragon NPU"
  ```
* Verify mathematical consistency:
  $$\text{Throughput (FPS)} = \frac{\text{batch\_size} \times 1000.0}{\text{median\_latency\_ms}}$$
* Check that all metrics carry the `[MEASURED]` provenance badge.

### 11. Output Numerical Fidelity & Accuracy Validation
* Compare original FP32 model outputs with optimized NPU outputs on identical deterministic test vectors:
  * **Cosine Output Similarity:** Must exceed `0.990`.
  * **Relative L2 Error:** Must remain below `0.02`.
  * **Top-1 Argmax Class Agreement:** Must be `YES` (`100%`).
  * **Numerical Integrity:** Zero NaN or Inf values.

### 12. Thermal, Battery & Power Consumption Profiling
* Hexagon NPU is designed for sustained 45 TOPS at sub-5W power envelopes.
* Record battery discharge rate using Nibble telemetry (`has_battery`, `battery_percent`).
* Compare CPU utilization: CPU load should remain $< 5\%$ during sustained NPU inference.

### 13. Deployment Bundle Packaging & Provenance Reporting
* Verify that the reproducible benchmark bundle is generated:
  ```text
  reports/benchmark_<timestamp>_<model_name>/
      ├── result.json
      └── summary.md
  ```
* Check that both original and optimized model SHA-256 hashes are recorded.
* Confirm that `OptimizationScorecard` issues a `HIGHLY RECOMMENDED` verdict for Snapdragon NPU deployment.
